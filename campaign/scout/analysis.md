## 1. How the analysis layer loads and selects

**Loading.** Two stacks, both keyed on a hard-coded root: `style.load_results(name, results_root='../experiment_results')` (style.py:142) globs **only top-level `{scan}/*.jsonl`** (style.py:166), one JSON line per run, and `_slim_record` drops `svd_info` + the per-batch loss/time keys (style.py:14-25). Heavy arrays live in `{scan}/diag/{run_id}.npz` and are pulled per run by `style.load_diagnostics` / `sv_diagnostics.batch_curve` / `epoch_spectra`. Because the glob is top-level only, the **move-aside convention** works by relocating superseded files into subdirs; verified present: `toy_1d_scan/_adamw_wd0`, `_spectra_truncated`, `cifar10_resnet_ce_scan/_frozen_bn`. `C-R3`'s `_stale/`, plus `manifest/`, `configs/`, `ckpt/`, are invisible to the loader for free.

**Cache.** `{results_root}/_cache/{name}.slim.pkl`, key = `_dir_signature` (blake2b over name/size/mtime_ns of every file) + `_CACHE_VERSION=3` (style.py:126-139). Verified: 17 pickles in `experiment_results/_cache`; cold load toy_1d_scan (734 files) **15.7 s**, cached **4.8 s**; mnist_scan_ce (1040) **23.4 s / 6.3 s** — warm cost is the per-file `stat()`. The cache write is **unguarded** (`cache.parent.mkdir`, `tmp.write_bytes`, style.py:199-205): a genuinely read-only legacy root raises.

**Configuration identity.** Two incompatible schemes. `scan_analysis` uses *explicit* key lists `SVEN_CONFIG=['k','lr','rtol']` / `BASELINE_CONFIG=[optimizer,lr,weight_decay,lbfgs_max_iter,lbfgs_history_size,tau,aggregator,inner_optimizer]` (scan_analysis.py:43-45) — safe against new columns. `analysis_helpers.config_columns` **auto-detects every scalar column** minus a small denylist `_NOT_CONFIG` (analysis_helpers.py:72-83) — *not* safe. Verified on toy_1d_scan it already treats `n_params`/`n_train`/`n_val`/`gram_freeze_norm_stats` as configuration keys (28 keys, 148 groups; sizes 145×5, 2×4, 1×1 — no fragmentation *yet* only because reruns replace whole configs).

**Selectors.** `Scan.configs` (scan_analysis.py:267) → mean/std/min of one metric per key tuple, `n_seeds`/`n_diverged`/`n_missing = len(self.seeds) − …`, `eligible` via `style.config_eligible`, sorted `eligible → n_diverged → score → (k, rtol desc, lr)`; `best_sven` / `best_baseline` return hparam dicts (:305, :317). `analysis_helpers.config_table` (:86) is the same rule over auto-detected keys, feeding `best_per_method`, `seed_mean_best`, `epochs_to_target_table`. Divergence is one function, `style.is_diverged(train_curve, val_curve)` (style.py:510) — **curves only, no status argument**; two call sites (`add_derived`, `Scan.__post_init__`).

**Timing join.** `attach_standalone_times(scan)` (scan_analysis.py:738) loads `{scan}_timing` and maps by `run_id` onto `scan.df/.sven/.baseline`, adding `standalone_{total_time,avg_epoch_time,avg_batch_time_train,avg_batch_time_val,peak_gpu_mem_mb}` + `…_time_excl_first_epoch`, and injects `losses['epoch_times_standalone']` in place; `resolve_time_key`/`time_axis_label`/`plot_time_summary(source='auto')` switch on it; it also reports final-val-loss deviation scan-vs-standalone. `bench/select_best_configs.py` calls `load_scan` → `best_sven`/`best_baseline` and writes `bench/best_configs.json`; `bench/timing_serial.sbatch` (RESELECT=1) re-derives it on the reserved node then emits `tag|override` lines per method. So the selection rule is already single-sourced from `scan_analysis`.

## 3. What a results-root switch requires

Four independent hard-codings (all verified by grep): `style.load_results`/`load_diagnostics` defaults `'../experiment_results'` (style.py:47,142,224), `scan_analysis.RESULTS_ROOT` (:35), `sv_diagnostics.RESULTS_ROOT` (:44), `profile_helpers.RESULTS_ROOT='../profile_results_v2'` (:28); writer side `generic_scan.py:347` `output_dir = "experiment_results"`. **No notebook passes `results_root`** — only `comparisons.ipynb` threads `scan.results_root` into `sv_diagnostics`. So one env-overridable `style.RESULTS_ROOT` (e.g. `SV3_RESULTS_ROOT`) imported by the other three modules makes the legacy/fresh switch a one-line notebook cell; `repair_legacy.py` then names the legacy root explicitly. Also required: guard the `_cache` write, and give `load_results` a `cache_dir` so a read-only legacy root still loads.

## 4. Notebook execution and what breaks

`make_plots.sh` (repo root) does `cd analysis` then `jupyter nbconvert --to notebook --execute --inplace <nb> --ExecutePreprocessor.timeout=3600`, in three groups: SCANS (4 + comparisons), STUDIES (10), PROFILES (4). Every notebook starts with `sys.path.insert(0,'.')`, kernelspec `python3`, `set_style()`, and writes to `plots_v2/<name>/`. **Verified blockers on this checkout:** `nbconvert`/`nbclient`/`nbformat` are **not installed** in `.venv` (pyproject dev extra is `ipykernel` only), and the bare `jupyter` on PATH (`~/.local/bin/jupyter`) is broken (`No module named jupyter_core`). `analysis/plots_v2/` does not exist locally (the committed executions ran elsewhere: cell metadata gives last run 2026-09-18 01:48–02:21 UTC). Re-execution itself is cheap — verified per-notebook cell-time sums 0.9–12.5 s warm; the real cost is cold cache rebuilds (~20 s × 38 scan dirs ≈ 13 min).

**Breakages when records gain `status`/test columns and spectra go full width:** (a) `analysis_helpers.config_columns` will absorb `status`, `run_hash`, `git_sha`, `git_dirty`, `host`, `slurm_job_id`, `gpu`, timestamps, `n_shards`, `n_test`, `steps_per_epoch` as configuration keys — every run becomes its own config and all seven `analysis_helpers` notebooks silently collapse (must flip to an allowlist, or extend `_NOT_CONFIG` + add a provenance denylist); `style.average_over_seeds`' auto-detection (style.py:346-357) has the identical flaw. (b) `status=='error'` rows will have short/absent curves: `Scan.n_epochs` and `epoch_axis` both read `rows.iloc[0]['losses']['train']` and will mis-size epoch axes and `epoch_spectra`'s step→epoch binning. (c) `plot_epoch_spectra`'s truncation warning inverts meaning and its x-normalisation breaks (§2). (d) `sv_min` must be renamed (F20) — it is produced in `_split_diagnostics` (generic_scan.py:211) and consumed in `style._attach_diagnostics`. (e) `profile_helpers.load_profiles` cache key is still the **weak** `(len(files), max mtime, configs)` (:98) with **no version field** — contradicting `ANALYSIS_FIXES` B18's "done"; after C-T2 it will serve stale `step_ms` unless a version is added.

## 5. Risks and proposed work packages

**Spec gaps.** (i) C-A2 says "no selector takes a test metric" but `quantity=` in `plot_knob_summary`/`plot_time_vs_k` reaches `configs()` as the metric — the assertion must live inside `configs`/`config_table`, not at the notebook. (ii) C-A1 needs `n_val` and the val-loader's `drop_last` convention, neither recorded pre-2026-09-17. (iii) C-L2 replaces `svd_spectra_every` with a schedule, but `svd_summary.spectra_every` is consumed by `sv_diagnostics` docs/`epoch_spectra` binning through `n_steps`; the schedule must stay recoverable per run. (iv) C-T2's acceptance "gram_hooks stays at 10.40" is 10.43 under cycle_mean — state a tolerance. (v) `make_plots.sh` needs `nbconvert` in the venv and `.venv/bin/jupyter` (not bare `jupyter`) before Phase 7 can run at all. (vi) Nothing in the analysis currently knows about `{scan}_timing` selection drift once run hashes change; `select_best_configs.py` should also emit the hash of the config it timed.
