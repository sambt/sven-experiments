**Decisions / deviations**
- **O6 → vendor, not drop.** The vendored path is validated to exactness against stock Muon, so Muon/MuonW can stay on CIFAR.
- `MuonConv` handles only **>2-D** hidden weights; 2-D hidden weights keep going to **stock `torch.optim.Muon`** (MLP/GPT path runs unmodified torch code). Combined via the existing `_CombinedOptimizer(*opts)` with 2 or 3 members.
- `adjust_lr_fn` for conv kernels uses the **flattened** shape; torch's `_adjust_lr` reads `param.shape[:2]`, which would ignore the kernel extent. Consequence to expect: `match_rms_adamw` scales the Muon lr by `0.2·sqrt(max(A,B))` (e.g. 13.6× for a 512×4608 flattened kernel, 11.1× for GPT-2's 768×3072) — intended by the rule, but it moves the Muon baseline (scout risk 7).
- **New hard failure**: if a model has no hidden weight matrix (`MultiMLP`, a single-`Linear` model), `Muon`/`MuonW` now raises `ValueError("… no hidden weight matrix …")` instead of silently being AdamW under a Muon label. No current config hits this (`MultiMLP` is used by no model config).
- `MultiLinear`'s `(num_models, out, in)` weight goes to AdamW (flattening would orthogonalise across ensemble members) — documented in `muon_param_groups`.
- Grouping rule is registration-order based (= forward order for every `experiments/nn` model): embeddings → AdamW; last Linear/Conv = head → AdamW; first Linear/Conv = input layer → AdamW **unless** the model has an embedding (then the embedding is the input layer and the first Linear is hidden); remaining Linear/Conv weights → Muon/MuonConv; everything else (1-D, unrecognised ≥2-D) → AdamW. Tied params returned once.
