## C-R1 — every failure is a record
`_classify_failure(exc) -> (status, diverged_at_step)` with `_OOM_ERRORS`/`_LINALG_ERRORS`/`_OOM_MESSAGE_TOKENS`/`_DIVERGED_MESSAGE_TOKENS`; order: `DivergedError` (carries `.step`) → OOM class → `"out of memory"` message → `LinAlgError` → `"no singular value above rtol"`/`"failed to converge"`/`"ill-conditioned"` → `error`.
`execute(spec, ctx, run_hash=None, prov=None) -> status`: pre-binds `optimizer/train_model/checkpointer/run_loaders=None`, `losses={}`, `timing=provenance.start_stamp()`; the `except` classifies, stores `error={"type","message"}` (2 kB cap), falls back to `getattr(exc,"losses")`; `finally` flushes the checkpointer + `torch.compiler.reset()`; the record is assembled and `_write_run` called **outside** the `try`, so ok/diverged/oom/error share one shape (with `svd_info`, `actual_param_fraction`, `ckpt_error`, `ckpt_file`). `_run_facts` tolerates `run_loaders=None`. `grid.resolve_scan_settings`: `stop_on_nonfinite` default **True**.

## C-R2 — manifest
`_manifest_job_name(rcfg)` = `{mode}.{build_id_string}.{optimizers}.{loss}.mseed…` — the **work item**, not `$SLURM_JOB_ID` (that accumulates manifests from grids nobody intends; `n_data` is an item axis in `plan_campaign.yaml`, so `result_id_fields` must be in the name). `claims.write_manifest(…, [s.run_id for s in specs], shard_id=… if static)` declares the full grid of the worker's subset.

## C-R3 — identity, dedup, provenance
`grid.run_hash`'s docstring now states the final rule; eval settings are hashed **resolved**, so spelling out a default is the same run. In: schema_version, family, hparams, batch size, three seeds, dataset+model configs (after the LM `cfg.model` mutation), loss, `num_epochs`, every `record_extra` input incl. `bn_mode` and `muon_rule`, eval settings. Out: `checkpoints`/`checkpoints_svd`, spectra schedule, `empty_cache`, `svd_info`, `stop_on_nonfinite`, `scheduler`/shards, derived echoes.
`run_grid` per run: `compute_run_hash` → `claims.is_done(index,·)` → `try_claim` → `is_done_now` → `_stale_hashes_now` + `move_to_stale` → `Heartbeat` + `mark_started` → `execute` → `mark_done` (LAST) → `finally clear_started`/`release`. **`_stale_hashes_now`** (new) is a fresh per-run glob of `done/{run_id}.*`: the process-start index cannot see a generation written after its listdir, and the artefact paths carry no hash, so the old jsonl/npz/ckpt would be *overwritten* instead of retired. `_save_resolved_config` → `{scan}/configs/{job}.yaml` (temp+`os.replace`). `provenance.collect(REPO_ROOT, SVEN_ROOT, n_shards=, shard_id=)` once per job, roots from `__file__` so a snapshot reports its `DEPLOY_INFO.json`. `_INDEX_REFRESH_RUNS=200`.

## Gaps
No mop-up pass (a worker that finishes the list while siblings run exits; resubmission mops up). `ctx.seed_state()` is before the `try`, so a broken `cfg.model` kills the worker with no record (deliberate — it is identical for every run). A `_write_run` failure (quota) propagates and exits non-zero: no record, no marker, retried. Timeout/SIGKILL leaves only `started/`, as designed. **Fork-after-torch:** a process forked from a torch-warmed pytest session deadlocks in libgomp — reproduced (both children hung past a 240 s join with claim+started markers on disk and 0 records), so the concurrency test stubs `execute`; real multi-process concurrency is the smoke's job.
